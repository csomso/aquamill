# Aquamill

웹 기반 실내서핑(시트 웨이브 / 플로우보딩) 프로토타입.

```bash
npm install
npm run dev
```

## 조작 (마우스 = 목표 무게중심, 화면 기준)

| 입력 | 동작 |
|---|---|
| 마우스 아래/위 | 앞/뒤 하중 — 경사 아래로 내려가기 / 위로 올라가기 |
| 마우스 좌/우 | 양발에 고르게 실린 상태면 보드 방향 그대로 옆으로 평행 이동 |
| 마우스 위 + 좌/우 | 뒷발에 싣고 앞을 밂 — 노즈가 그쪽으로 돈다 |
| 마우스 아래 + 좌/우 | 앞발에 싣고 뒷발을 밂 — 테일이 그쪽으로 (노즈는 반대로) 돈다 |
| 좌클릭 누르고 떼기 | 웅크렸다 점프 (오래 누를수록 높게) |
| 좌클릭 누른 채 우클릭 드래그 / 휠 | 샤빗 토크 감기 — 좌클릭을 떼며 점프하는 순간 보드를 찬다 |
| Shift + 우클릭 드래그 / Shift + 휠 | 몸 돌리기 (바닥에선 보드째, 공중에선 몸만) |

마우스는 "가고 싶은 무게중심"만 정한다. 실제 몸 무게중심은 스프링처럼 시간을 두고 따라가고(HUD 흰 고리),
엣지도 물에 서서히 박히므로 무게를 실어도 바로 그쪽으로 가지 않는다. 끝에서 반대 끝으로 확 옮기면 균형을 잃는다.

라이더는 보드 위에 옆으로 선다(어깨선 = 보드 길이 방향, 가슴 = 폭 방향). 레귤러는 화면 왼쪽을 본다.
보드는 트윈팁이라 앞뒤가 없고, 레귤러/페이키는 몸이 어느 쪽을 보는지(앞발이 어느 쪽인지)로만 정해진다.

- 바닥에선 발이 보드에 붙어 있어 몸과 보드가 함께만 돈다 (서피스 180/360)
- 샤빗(보드만 회전)은 점프 순간 보드를 찬 토크로만 돈다. 공중에선 그 각속도 그대로라 바꿀 수 없다
  깊이 웅크렸다 뛸수록 세게 찰 수 있다. 낮은 점프는 180 까지, 360 은 최대로 웅크린 높은 점프에 거의 최대 토크여야 되고 540 은 안 된다.
  차지 않은 점프는 보드가 발에 붙어 몸과 같이 돈다
- 착지할 때 보드가 흐름 방향이고 발이 보드 위에 옆으로 설 수 있는 각도가 아니면 착지 실패
- 몸이 180 돌면 앞발이 바뀌어 페이키

- 뒤로 너무 실으면 크레스트 너머로 넘어간다.
- 보드가 돌아간 상태에서 무게를 앞(경사 아래)에 실으면 물을 맞는 레일이 파고들어 고꾸라진다 (HUD 빨간 게이지).
  무게를 중앙~뒤에 두면 물살이 보드를 다시 정렬시켜 서피스 360 으로 마무리된다.

## 발 위치

오른쪽 위 패널에서 앞발/뒷발 위치를 바꾼다 (ESC 로 포인터 잠금을 풀고 조절). 기본값은 실제 플로우보드처럼
앞발은 중심에서 살짝 앞, 뒷발은 테일 끝.

- 지렛대: 마우스 위/아래는 두 발 사이의 체중 배분이고, 보드를 누르는 지점(하중 지점)은 두 발 위치 사이에서 정해진다.
  뒷발이 테일 끝이라 뒤로 실으면 노즈가 확 들려 강하게 감속/상승하고, 앞발이 중심 근처라 앞으로 실어도 가속은 완만하다.
  발을 통째로 앞으로 옮기면 중립에서도 내려간다.
- 피벗: 바닥에서 보드는 하중 지점을 축으로 돈다. 뒷발에 실으면 테일 피벗(빠르게 돎), 앞발에 실으면 넓고 부드러운 카빙.

## 구조

```
src/input/types.ts    RiderInput — 장치 독립 입력 계약 (몸 기준 목표 하중, yaw, bodyYaw, crouch, pop)
src/input/mouse.ts    마우스 어댑터 (Pointer Lock, 중앙 복원 스프링)
src/physics/rider.ts  시트 웨이브 위 보드 물리 (고정 스텝 120Hz)
src/render/canvas.ts  Canvas 2D 탑뷰 렌더러 + HUD
src/ui/feetPanel.ts   발 위치 설정 패널
src/main.ts           게임 루프
```

물리 엔진은 `RiderInput`만 본다. 새 입력 장치는 `InputSource`를 구현하는 어댑터만 추가하면 된다.

- 모바일: 두 엄지 = 두 발. 같은 방향으로 밀면 roll, 반대 방향이면 yaw
- 웹캠: MediaPipe Pose로 골반·어깨 중심을 압력중심으로, 무릎 굽힘을 crouch로
